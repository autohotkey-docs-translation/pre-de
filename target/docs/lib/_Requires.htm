#Requires

Deklariert die Anforderungen des Skripts und setzt potentiell den Kompatibilitätsmodus.

#Requires Anforderung

Parameter

Anforderung

Typ: Zeichenkette

Wenn dieser Parameter nicht mit dem Wort "AutoHotkey" beginnt, wird eine Fehlermeldung angezeigt und das Programm beendet. Dies dient der Übersichtlichkeit und reserviert die Direktive für zukünftige Zwecke. Andere Entwicklungszweige von AutoHotkey können andere Namen unterstützen.

Andernfalls muss nach dem Wort "AutoHotkey" eine beliebige Kombination der folgenden Zeichen angegeben werden, getrennt durch Leer- oder Tabulatorzeichen:

  • Ein optionales "v", unmittelbar gefolgt von einer Versionsnummer. A_AhkVersion muss größer gleich diese Version, aber kleiner als die nächste Hauptversion sein.
  • <, <=, >, >= oder =, unmittelbar gefolgt von einem optionalen "v" und einer Versionsnummer. >=2-rc <2 erlaubt zum Beispiel v2 Release Candidates, aber nicht die finale Version.
  • Eines der folgenden Wörter, um den Typ der EXE-Datei einzuschränken, die das Skript ausführen darf: "32-bit", "64-bit".

Fehlermeldung

Die angezeigte Meldung ist abhängig von der Version von AutoHotkey, die die Direktive interpretiert.

Die Fehlermeldung zeigt immer den Pfad, die Version und den Build von AutoHotkey an.

Wenn das Skript mit einer Version von AutoHotkey gestartet wird, die diese Direktive nicht unterstützt, sieht die Fehlermeldung in etwa so aus:

Line Text: #Requires %Anforderung%
Error: This line does not contain a recognized action.

Kompatibilitätsmodus [v2.1-alpha.34+]

Die Angabe einer Versionsanforderung (oder mehrerer Anforderungen in einer Direktive) kann dazu führen, dass der Kompatibilitätsmodus für das aktuelle Modul und nachfolgende Funktionen oder Direktiven aktiviert wird. Der v2.0-kompatible Modus ist aktiv, wenn Version "2.0.x" die Anforderungen erfüllt; andernfalls ist er deaktiviert. Wenn die Direktive nicht verwendet wird, gilt standardmäßig der v2.0-Modus. Die Verwendung der Direktive ohne Versionsangabe hat keinen Einfluss auf den Modus.

Hinweis: Das Laufzeitverhalten richtet sich nach dem Modus des aktuellen Moduls oder der aktuellen Funktion, nicht nach der Position der Direktive bezüglich der aktuellen Zeile oder Datei.

Die erste, in jedem Modul verwendete Versionsdirektive bestimmt den Laufzeitmodus für den gesamten Startcode dieses Moduls in allen Dateien.

Versionsdirektiven werden beim Laden des Skripts geparst, um den Modus für nachfolgende Funktions-/Methodendefinitionen und #Include <BiblName>-Direktiven zu bestimmen. Dieser Effekt ist positionsabhängig und kann innerhalb eines einzelnen Moduls beliebig oft variieren.

#Module setzt den Standardmodus des neuen Moduls auf den des __Init-Moduls.

Versionsdirektiven beschränken ihren Gültigkeitsbereich auf Modul-, Datei- oder Funktionsebene. Mit anderen Worten:

  • Die Verwendung der Direktive innerhalb eines Moduls beeinflusst andere Module nur, wenn sie die erste Direktive ist, wie oben beschrieben.
  • Die Verwendung der Direktive innerhalb einer #Include-Datei beeinflusst weder das äußere Modul noch Funktionen, die in der äußeren Datei definiert sind.
  • Die Verwendung der Direktive innerhalb einer Funktion beeinflusst nur verschachtelte Funktionen.

Durch den korrekten Einsatz von Versionsdirektiven können Codeabschnitte, die für verschiedene Versionen geschrieben wurden, gemeinsam in einem Skript stehen.

  • Ein v2.1-Modul oder eine v2.1-Funktion kann bedenkenlos v2.0-Funktionen enthalten.
  • Eine v2.0-Datei, die ausschließlich Funktions- und Klassendefinitionen enthält, kann mittels #Include bedenkenlos in ein v2.1-Modul inkludiert werden.
  • Ein ursprünglich für v2.0 geschriebenes Skript kann schrittweise, Funktion für Funktion, aktualisiert werden. Neue Funktionen können sich den v2.1-Modus zunutze machen, während der Rest des Skripts im v2.0-Modus bleibt.
  • Die Modi v2.0 und v2.1 dürfen im globalen Code bzw. im Startcode eines einzelnen Moduls nicht gemischt werden, selbst wenn der Code aus mehreren Dateien stammt. Generell ist es am sichersten, v2.0-Dateien und v2.1-Dateien voneinander zu trennen, indem man sie in separaten Modulen unterbringt.

Einzelheiten dazu, wie sich der Modus auf das Verhalten des Skripts auswirkt, finden Sie unter Kompatibilitätsmodus (Änderungen).

Das Kompatibilitätsmodusbeispiel unten zeigt, welchen Effekt die Versionsdirektiven auf den Kompatibilitätsmodus haben.

Bemerkungen

Da der Launcher die gleichzeitige Nutzung von v1- und v2-Skripten auf einem System ermöglicht, empfiehlt es sich, zumindest #Requires AutoHotkey v1 für v1-Skripte und #Requires AutoHotkey v2 für v2-Skripte hinzuzufügen. Dadurch wird sichergestellt, dass die richtige Version zum Ausführen des Skripts verwendet wird.

Wenn das Skript Syntaxelemente oder Funktionen verwendet, die in früheren Versionen nicht verfügbar sind, können Sie mit dieser Direktive sicherstellen, dass die Fehlermeldung die unerfüllte Anforderung und nicht einen willkürlichen Syntaxfehler anzeigt. Das ist mit so etwas wie if (A_AhkVersion <= "1.1.33") nicht möglich, weil ein Syntaxfehler an anderer Stelle im Skript dessen Ausführung verhindern würde.

Wenn Sie ein Skript mit anderen teilen oder den Code ins Internet stellen, können Sie mit dieser Direktive sicherstellen, dass jeder, der den Code findet, schnell erkennen kann, für welche AutoHotkey-Version dieser Code gedacht ist.

Andere Programme oder Skripte können diese Direktive für verschiedene Zwecke überprüfen. Der Launcher von AutoHotkey v2 verwendet diese Information zum Beispiel, um festzustellen, welche EXE-Datei von AutoHotkey gestartet werden soll, während ein Skripteditor oder ähnliche Tools diese Information beispielsweise verwenden können, um festzustellen, wie die Skriptdatei interpretiert oder farblich hervorgehoben werden soll.

Versionszeichenketten werden als eine Reihe von via Punkt getrennten Komponenten verglichen, optional gefolgt von einem Bindestrich und Vorabversionsidentifikator(en).

  • Numerische Komponenten werden numerisch verglichen. Zum Beispiel ist v1.01 = v1.1, aber a20 > a112.
  • Innerhalb derselben Position werden numerische Komponenten gegenüber nicht-numerischen Komponenten immer als niedriger angesehen.
  • Jede fehlende via Punkt getrennte Komponente wird als Null behandelt. Zum Beispiel ist v1.1.33-alpha dasselbe wie v1.1.33.00-alpha.0.
  • Nicht-numerische Komponenten werden alphabetisch verglichen und sind Groß-/Kleinschreibung-sensitiv.
  • Vorabversionen werden gegenüber den Standardversionen als niedriger angesehen. Zum Beispiel wird ein Skript mit #Requires AutoHotkey v2 unter v2.0-a112 nicht ausgeführt. Um Vorabversionen zu erlauben, fügen Sie einen Bindestrich hinzu. Zum Beispiel: v2.0-.
  • Alle Suffixe, die mit "+" beginnen, werden ignoriert.

Ein "+" am Ende genügt, um den Leser darauf hinzuweisen, dass spätere Versionen akzeptabel, aber nicht erforderlich sind.

#Requires kann wie alle anderen Direktiven nicht bedingt ausgeführt werden.

Beispiele

Bewirkt, dass das Skript nur in v2.0 inklusive Alpha-Versionen läuft.

#Requires AutoHotkey v2.0-a
MsgBox "Dieses Skript läuft nur in v2.0 inklusive Alpha-Versionen."

Bewirkt, dass das Skript nur in v2.0 inklusive Vorabversionen läuft.

#Requires AutoHotkey >=2.0- <2.1

Bewirkt, dass das Skript nur mit einem 64-Bit-Interpreter (EXE) läuft.

#Requires AutoHotkey 64-bit

Bewirkt, dass das Skript nur mit einem 64-Bit-Interpreter (EXE) der Version 2.0-rc.2 oder höher läuft.

#Requires AutoHotkey v2.0-rc.2 64-bit

Zeigt, welchen Effekt die Versionsdirektiven auf den Kompatibilitätsmodus haben. 

; Diese unverzichtbare Zeile setzt den Modus für das aktuelle Modul (__Main).
#Requires AutoHotkey v2.1-alpha.33

; Mit try-catch den Modus ermitteln. Base liefert "" im v2.0-Modus und unset im v2.1-Modus.
; ?? wird hier nicht verwendet, da es in beiden Modi für "leere-ungesetzte" Rückgabewerte funktioniert.
try
    MsgBox Type(Any.Prototype.Base), "Main #1"
catch UnsetError
    MsgBox "UnsetError", "Main #1"

; Wenn Sie diese beiden Direktiven vertauschen, können Sie beobachten, welchen Einfluss das auf die Initialisierung von CompatibleLib hat.
#Import "CompatibleLib.ahk" {CompatibleFunc}
; #Include "CompatibleLib.ahk"

CompatibleFunc()
MainFunc()

; Direktiven in einem #Include oben haben keinen Effekt auf dieses Modul.
try
    MsgBox Type(Any.Prototype.Base), "Main #2"
catch UnsetError
    MsgBox "UnsetError", "Main #2"

HauptFunk() {
    try
        MsgBox Type(Any.Prototype.Base), "MainFunc"
    catch UnsetError
        MsgBox "UnsetError", "MainFunc"
}

CompatibleLib.ahk:

#Requires AutoHotkey v2.0

; Wird Folgendes in ein v2.1-Modul inkludiert, wird es einen Fehler auslösen.
try
    MsgBox Type(Any.Prototype.Base), "CompatibleLib"
catch UnsetError
    MsgBox "UnsetError", "CompatibleLib"

; Die Funktion unten nutzt immer den v2.0-Modus, wegen der Direktive oben.
CompatibleFunc() {
    try
        MsgBox Type(Any.Prototype.Base), "CompatibleFunc"
    catch UnsetError
        MsgBox "UnsetError", "CompatibleFunc"
}
