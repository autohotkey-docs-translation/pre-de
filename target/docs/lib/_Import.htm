#Import [v2.1-alpha.20+]

Importiert ein Modul und optional Namen aus einem Modul.

#Import Export ModulName as ModulAlias { *, ExportName ... }

Parameter

ModulName

Ein Modulname, ein Pfad oder einen Ressourcenbezeichner. Es muss entweder ein gültiger Identifikator oder eine direkt geschriebene Zeichenkette sein. Beim Importieren eines via #Module definierten Moduls oder einer Datei kann jedoch eine beliebige Syntax verwendet werden.

Pfade können absolut oder relativ zu den Suchverzeichnissen sein.

Um ein eingebettetes Skript als Modul zu laden, geben Sie ein Sternchen gefolgt vom Ressourcennamen an. Zum Beispiel: "*RESNAME".

[v2.1-alpha.21+]: Um ein Untermodul aus einer anderen Gruppe zu importieren, verwenden Sie einen pfadqualifizierten Namen im Format "Pfad:ModulName". Pfad sollte das Hauptmodul der Gruppe identifizieren, das entweder das Skript selbst oder eine via #Import importierte Datei ist.

ModulAlias

Ein Identifikator, der innerhalb des aktuellen Moduls verwendet werden soll, um auf das importierte Modul zu verweisen.

ExportName

Ein Identifikator, der aus dem Modul exportiert wird.

[v2.1-alpha.21+]: Dies kann der Name einer beliebigen Funktion, Klasse oder globalen Variable sein, einschließlich der Aliase der Namen, die das Modul importiert hat.

Alias

Ein Identifikator, der innerhalb des aktuellen Moduls anstelle von ExportName verwendet werden soll.

Import aus einer Datei

Importe werden verarbeitet, nachdem die Hauptskriptdatei geparst wurde, in einer unbestimmten Reihenfolge. Wenn ModulName (ohne Anführungszeichen) kein Modul findet, das via #Module definiert oder zuvor aus einer Datei importiert wurde, versucht #Import, eine Moduldatei zu lokalisieren und zu laden. Weitere Informationen finden Sie unter Suchpfad.

Importierte Namen

Das Modul selbst wird nur zum globalen Namensraum des aktuellen Moduls hinzugefügt, wenn ModulAlias angegeben oder ModulName anführungszeichenlos ist.

Wenn * verwendet wird, kann jeder nicht zugewiesene und nicht deklarierte Name im aktuellen Modul implizit zu einem aus ModulName exportierten Namen aufgelöst werden. Wenn ein Name aus mehreren importierten Modulen exportiert wird, hat der letzte Import Vorrang. Explizite Importe und andere Deklarationen haben Vorrang vor impliziten Importen, unabhängig von der Reihenfolge.

[v2.1-alpha.31+]: Jedes Modul exportiert alle globalen Namen, die nicht mit einem Unterstrich beginnen, außer Namen, die ohne das Schlüsselwort Export importiert wurden.

Hinweis: Eine implizit importierte Variable kann nicht das Ziel einer Zuweisung sein, da die Existenz einer Zuweisung dazu führen würde, dass eine neue Variable im aktuellen Modul erstellt wird.

Es wird ein Ladezeitfehler ausgelöst, wenn ein Name, der in einem expliziten Import verwendet wird, auch in einer anderen Deklaration innerhalb des aktuellen Moduls verwendet wird.

Export [v2.1-alpha.31+]

Die importierten Namen werden nur exportiert (zugänglich für Platzhalterimporte in anderen Modulen), wenn das Schlüsselwort Export verwendet wird. Zum Beispiel:

#Module TestB
  #Import LibB {*}
  ; Sowohl B als auch F sind definiert.
  MsgBox Format("B: {}`nF: {}`n_internal: {}", B(), Type(F?), Type(_internal?)), "TestB"

#Module LibB
  #Import Export _internal {*}
  B() => Type(F?)

#Module TestA
  #Import LibA {*}
  ; Nur A ist definiert.
  MsgBox Format("A: {}`nF: {}`n_internal: {}", A(), Type(F?), Type(_internal?)), "TestA"

#Module LibA
  #Import _internal {*}
  A() => Type(F?)

#Module _internal
  F() => 0

Bemerkungen

Zeilenumbrüche können innerhalb der geschweiften Klammern verwendet werden, dank Fortsetzung durch Umschließen.

Klassen und Funktionen stehen bereits zur Verfügung, noch bevor das Quellmodul ausgeführt wurde, z.B. wenn das Modul, das sie importiert, aufgrund eines zirkulären Imports zuerst läuft.
