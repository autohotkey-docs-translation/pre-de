Class-Objekt

class Class extends Object

Ein Class-Objekt repräsentiert eine Klassendefinition; es enthält statische Methoden und Eigenschaften.

Jedes Klassenobjekt basiert auf der Klasse, die es erweitert, oder auf Object, falls nicht angegeben. Das globale Klassenobjekt Object basiert auf Class.Prototype, das wiederum auf Object.Prototype basiert, so dass Klassen Methoden und Eigenschaften von jedem dieser Basisobjekte erben können.

"Statische" Methoden und Eigenschaften sind alle Methoden und Eigenschaften, die dem Klassenobjekt selbst gehören (und daher nicht für eine bestimmte Instanz gelten), während Methoden und Eigenschaften für Instanzen der Klasse dem Prototyp der Klasse gehören.

"ClassObj" wird hier stellvertretend für ein beliebiges Klassenobjekt verwendet, da "Class" die Klasse selbst ist. Normalerweise wird auf ein Klassenobjekt via Name verwiesen, der in dessen Klassendefinition angegeben ist.

Inhaltsverzeichnis

  • Statische Methoden:
    • Call: Erstellt ein neues Class-Objekt.
  • Methoden:
    • Call: Konstruiert eine neue Instanz der Klasse.
  • Eigenschaften:
    • Prototype: Liefert oder setzt das Objekt, auf dem alle Instanzen der Klasse basieren.

Statische Methoden

Call

Erstellt ein neues Class-Objekt ohne Prototyp.

ClassObj := Class()
ClassObj := Class.Call()

[v2.1-alpha.3+]: Erstellt ein neues Class-Objekt basierend auf BasisKlasse oder Object.

ClassObj := Class(Name, BasisKlasse, Args*)
ClassObj := Class(BasisKlasse, Args*)
ClassObj := Class.Call(Name, BasisKlasse, Args*)
ClassObj := Class.Call(BasisKlasse, Args*)
Name

Typ: Zeichenkette

Wenn weggelassen, wird standardmäßig eine leere Zeichenkette verwendet. Andernfalls geben Sie einen Klassennamen an, den Sie ClassObj.Prototype.__Class zuweisen möchten.

BasisKlasse

Typ: Klasse

Wenn weggelassen, wird standardmäßig Object verwendet. Andernfalls geben Sie die Basisklasse an. ClassObj.Base wird auf diesen Wert gesetzt, während ClassObj.Prototype.Base auf BasisKlasse.Prototype gesetzt wird.

Args*

Falls angegeben, werden alle anderen Parameter an static __New übergeben, wie in ClassObj.__New(Args*).

Hinweis: Dies gilt für den direkten Aufruf von "Class" selbst, nicht für den Aufruf von Klassen.

Class() oder Class.Call() kann verwendet werden, um ein neues Class-Objekt basierend auf Class.Prototype zu konstruieren. Dieses neue Objekt hat jedoch zunächst keine Call-Methode, da es keine Unterklasse von Object ist. Es kann zu einer Unterklasse von Object durch Zuweisung an Base gemacht werden, oder die Call-Methode kann reimplementiert oder aus einer anderen Klasse kopiert werden. Außerdem muss ein Prototyp erstellt und der Klasse zugewiesen werden, bevor sie mit der Standard-Call-Methode instanziiert werden kann.

[v2.1-alpha.3+]: Class() oder Class.Call() kann mit Parametern aufgerufen werden. Aus Gründen der Abwärtskompatibilität verhält es sich wie im Absatz oben beschrieben, wenn die Parameteranzahl Null ist. Andernfalls (auch wenn ein Parameter explizit unset ist) wird automatisch ein Prototyp basierend auf BasisKlasse.Prototype erstellt. Dadurch können Skripte während der Ausführung Prototypobjekte erstellen, die auf anderen nativen Typen als Object basieren, z.B. Map und Array.

Ein Anwendungsbeispiel ist die Erstellung einer Strukturdefinition während der Skriptausführung.

Methoden

Call

Konstruiert eine neue Instanz der Klasse.

Obj := ClassObj(Params*)
Obj := ClassObj.Call(Params*)

Diese statische Methode wird typischerweise von der Object-, Array- oder Map-Klasse geerbt. Sie führt die folgenden Funktionen aus:

  • Speicher reservieren und die binäre Struktur des Objekts initialisieren, was vom nativen Typ des Objekts abhängt (z.B. ob es ein Array oder Map ist, oder ob es nur ein Object ist).
  • Die Basis des neuen Objekts auf ClassObj.Prototype setzen.
  • Die __Init-Methode des neuen Objekts aufrufen, falls sie eine hat. Diese Methode wird automatisch via Klassendefinitionen erzeugt; sie enthält alle im Klassenkörper definierten Instanzvariableninitialisierer.
  • Die __New-Methode des neuen Objekts aufrufen, falls sie eine hat. Alle an Call übergebenen Parameter werden an __New weitergeleitet.
  • Das neue Objekt zurückgeben.

Call kann innerhalb einer Klassendefinition durch Definieren einer statischen Methode überschrieben werden, z.B. static Call(). Auf diese Weise können Klassen die Konstruktion neuer Instanzen ändern oder verhindern.

Dies ist eine statische Methode insofern, dass sie zu einer Klasse (z.B. Object) gehört, gleichzeitig aber auch eine Instanzmethode des Klassenobjekts, das eine Instanz von Class ist. Die Class-Klasse selbst hat eine statische Call-Methode. Mit anderen Worten, man kann Class() oder Class.Call() aufrufen, um ein neues Klassenobjekt während der Skriptausführung zu erstellen.

Eigenschaften

Prototype

Liefert oder setzt das Objekt, auf dem alle Instanzen der Klasse basieren.

Proto := ClassObj.Prototype
ClassObj.Prototype := Proto

Der Prototyp der Klasse enthält standardmäßig alle Instanzmethoden und dynamischen Eigenschaften, die in der Klassendefinition definiert sind, und kann verwendet werden, um Referenzen zu Methoden oder Eigenschafts-Getter/Setter abzurufen oder neue zu definieren. Das Skript kann zudem neue Werteigenschaften definieren, die als Standardeigenschaftswerte für alle Instanzen dienen.

Der Prototyp einer Klasse basiert normalerweise auf dem Prototyp ihrer Basisklasse, folglich ist ClassObj.Prototype.base == ClassObj.base.Prototype.

Prototype wird automatisch als eigene Eigenschaft eines Klassenobjekts, das via Klassendefinition erzeugt wurde, definiert.

[v2.1-alpha.28+]: Aus Gründen der Sicherheit und Effizienz haben Strukturklassen einen schreibgeschützten Prototyp.

ClassObj() und Wert is ClassObj setzen voraus, dass die Prototype-Eigenschaft eine Werteigenschaft ist, die direkt zur Klasse gehört, es sei denn, sie ist eine Struct-Klasse. Den Wert dieser Eigenschaft zu ändern, wirkt sich in der Regel nur auf diese beiden Operationen und auf direkte Referenzen zu ClassObj.Prototype aus. Zuvor erstellte und anderweitig konstruierte Objekte sind in der Regel nicht davon betroffen, allerdings werden sie eventuell nicht mehr als Instanzen der Klasse erkannt.

Bis auf einige Ausnahmen konstruieren interne Funktionen Objekte gewöhnlich auf Basis eines bekannten Prototyps und sind daher von Änderungen an der Prototype-Eigenschaft nicht betroffen.
