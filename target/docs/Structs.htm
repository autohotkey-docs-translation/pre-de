Strukturen

Eine Struktur oder struct ist eine Sammlung von Elementen (Feldern), die nebeneinander im Speicher abgelegt sind.

Strukturen werden häufig bei externen Funktionen via DllCall oder bei GUI-Steuerelementen via SendMessage verwendet. In solchen Fällen muss der Speicher-Offset jedes Feldes relativ zum Anfang der Struktur genau mit dem Offset übereinstimmen, den die externe Funktion oder das Steuerelement erwartet – in der Regel so, wie er in einem SDK oder in der Dokumentation für C/C++-Entwickler definiert ist.

In AutoHotkey v2.0 und älteren Versionen wurden Strukturen in der Regel "definiert", indem man Speicher mit z.B. Buffer reservierte und diesen anschließend direkt mit NumPut und NumGet manipulierte. Für diesen Vorgang müssen die Offsets für jedes einzelne Feld berechnet werden. Das ist ziemlich mühsam und fehleranfällig. Felder werden grundsätzlich nicht per Name referenziert, was die Lesbarkeit und Pflege des Codes erschwert.

Warnung: Dies ist eine Vorabdokumentation für v2.1. Details können sich mit jeder Alpha-Version ändern.

Ab v2.1 ist es möglich, eine Struktur in Form einer Sequenz typisierter Eigenschaften zu definieren. Dies ermöglicht es, Felder per Name anzusteuern, unterstützt durch die automatische Berechnung von Offsets und Strukturgrößen. In der Regel wird dafür eine Strukturklassendefinition verwendet. Allerdings können Strukturklassen auch während der Skriptausführung konstruiert werden.

Verwendung einer Klassendefinition [v2.1-alpha.22+]

Strukturklassen werden mit struct statt mit class definiert, und erweitern standardmäßig Struct statt Object.

Um ein Feld in einer Struktur zu definieren, muss zunächst dessen Name, dann ein Doppelpunkt und anschließend ein Typbezeichner angegeben werden. Dies wird auch als typisierte Eigenschaft bezeichnet. Es ist möglich, mehrere typisierte Eigenschaften auf einer Zeile zu definieren, jeweils getrennt durch ein Komma. Zum Beispiel:

struct POINT {
    x : Int32, y : Int32
}

Bei der Konstruktion des Objekts werden alle Felder null-initialisiert, noch bevor die Initialisierer ausgewertet werden. Um ein Feld mit einem bestimmten Wert zu initialisieren, wird nach dem Typ eine Zuweisung eingefügt. Zum Beispiel:

struct LVINSERTMARK {
    cbSize      : UInt32 := this.Size
    dwFlags     : UInt32
    iItem       : Int32
    dwReserved  : UInt32
}

Eine Strukturklasse kann auf die übliche Weise instanziiert werden, indem sie aufgerufen wird:

im := LVINSERTMARK()

Da Strukturen häufig aus externen Quellen stammen, kann mithilfe der At-Methode eine Adresse in eine Referenz umgewandelt werden, die auf eine Struktur verweist.

Felder einer Unterklasse werden immer hinter den Feldern der Basisklasse platziert. Wenn z.B. die Klasse StructB die Klasse StructA erweitert, ist das Layout dasselbe wie, als würde StructB die Klasse Object erweitern, jedoch beginnend mit einer verschachtelten StructA. Der Zugriff auf geerbte Eigenschaften erfolgt allerdings nicht über eine verschachtelte Struktur, sondern direkt.

Mit #StructPack kann die Standardausrichtung der Felder innerhalb der Struktur überschrieben werden.

Alle Elemente einer Klassendefinition sind zulässig, aber ein Initialisierer wie z.B. x := 0 kann keine neue Eigenschaft erstellen.

Verwendung von DefineProp

Eine Struktur kann während der Skriptausführung definiert werden, indem man ein Class-Objekt erstellt und mittels DefineProp typisierte Eigenschaften zu seinem Prototyp hinzufügt. Zum Beispiel:

POINT := Class(Struct)  ; v2.1-alpha.21 und älter nutzten Object statt Struct.
DefineProp(POINT.Prototype, 'x', {type: Int32})
DefineProp(POINT.Prototype, 'y', {type: Int32})
pt := POINT()

Typischerweise wird das Klassenobjekt (POINT) einmal definiert und dazu verwendet, viele Instanzen (pt) zu erstellen.

Anders als bei Deklarationen in einer Klassendefinition müssen direkt geschriebene, reservierte Typnamen wie "i32" in Anführungszeichen gesetzt werden, wenn DefineProp aufgerufen wird.

Ähnlich wie bei einer Klassendefinition können Felder von der Basisklasse des Prototyps geerbt werden.

[v2.1-alpha.19+]: Mit Pack kann die Standardausrichtung der Felder innerhalb der Struktur überschrieben werden. Zum Beispiel:

AB := Class(Struct)
DefineProp(AB.Prototype, 'a', {type: Int8})
DefineProp(AB.Prototype, 'b', {type: Int32, pack: 1})
MsgBox AB().Size

Typbezeichner [v2.1-alpha.30+]

Ein Typbezeichner in einer Klassendefinition kann Folgendes sein:

  • Ein exakter Klassenname, wie z.B. KlasseName.VerschachtelteKlasse.
  • Ein in runde Klammern gesetzter Ausdruck.
  • Ein Ausdruck, der mit einem Identifikator beginnt, optional gefolgt von einer Parameterliste (was ihn zu einem Funktionsaufruf macht), optional gefolgt von einer beliebigen Anzahl von Eigenschaften oder Methodenaufrufen.

Typbezeichner werden nacheinander mit statischen Eigenschaftsinitialisierern ausgewertet, wenn die Klasse initialisiert wird (nicht jedes Mal, wenn sie instanziiert wird).

Der Typbezeichner muss bei der Auswertung eine Strukturklasse mit einer Größe ungleich Null ergeben. Die Auswertung erfolgt im Kontext static __Init(); d.h. this verweist auf das Klassenobjekt.

Eine Strukturklasse ist eine beliebige Unterklasse von Struct, einschließlich numerischer Typen, Arrayklassen, Pointerklassen und Struct.Ptr selbst.

Numerische Typen [v2.1-alpha.23+]

Es gibt für numerische Typen die folgenden vordefinierten Strukturklassen:

  • Int8, Int16, Int32 und Int64 sind vorzeichenfähige Integer; 8-Bit, 16-Bit, 32-Bit und 64-Bit.
  • UInt8, UInt16 und UInt32 sind vorzeichenlose Integer; 8-Bit, 16-Bit und 32-Bit.
  • IntPtr ist ein vorzeichenfähiger Integer; 32-Bit wenn A_PtrSize = 4, und 64-Bit wenn A_PtrSize = 8.
  • Float32 und Float64 sind Floating-Point-Zahlen.

Hinweis: AutoHotkey unterstützt keine vorzeichenlosen 64-Bit-Integer. Verwenden Sie stattdessen vorzeichenfähige Integer.

Da das Strukturklassen sind, verfügt jede über eine Pointerklasse und Arrayklassen. Zum Beispiel ist UInt32.Ptr dasselbe wie "UInt*" bei DllCall, und UInt8[64] ist die Klasse eines 64-Byte-Arrays.

Wenn diese Strukturklassen als Eigenschaftstypen, DllCall-Parametertypen oder Array-Elementtypen verwendet werden, erfolgt die Umwandlung direkt. Die Klassen werden dabei nicht instanziiert. Bei DllCall beinhaltet das auch die Pointerklassen. Ein Rückgabewert vom Typ Int32.Ptr ist zum Beispiel genau dasselbe wie "Int*" und dereferenziert immer den Pointer (gibt den Integerwert zurück, auf den er zeigt), anstatt einen gekapselten Pointer zurückzugeben.

Eine Instanz einer numerischen Strukturklasse agiert nicht als Zahl, sondern als virtuelle Referenz, die auf eine numerische Variable verweist. Wie bei Strukturinstanzen sprechen wir von einem gekapselten Pointer, wenn der Pointer unsicher ist, oder von einer gekapselten Struktur, wenn ihre Lebensdauer durch das Skript verwaltet wird. Eine Instanz kann wie folgt erstellt werden:

  • Der direkte Aufruf der Klasse erstellt eine gekapselte Struktur.
  • Eine Eigenschaft eines Pointertyps wie Int32.Ptr kann einen gekapselten Pointer zurückgeben.
  • Ein Rückruf kann einen eingehenden Pointerwert in einen gekapselten Pointer umwandeln, wenn der Parametertyp ein Pointertyp wie z.B. Int32.Ptr ist.
  • Die At-Methode erstellt einen gekapselten Pointer.

Jede Instanz hat eine Eigenschaft namens __Value, und zwar vom Typ, der durch die Klasse repräsentiert wird. In der Regel geschieht dies indirekt durch den Dereferenzoperator oder wenn die Instanz als virtuelle Referenz verwendet wird. Zum Beispiel würde MouseGetPos(Int32.at(pt.ptr)) die X-Koordinate am Anfang der Struktur pt speichern.

Verschachtelte Strukturen

Verschachtelte Strukturen werden in der Reihenfolge ihrer Definition erstellt, noch bevor die äußere Struktur initialisiert wird. Die eigenen Feldinitialisierer der verschachtelten Struktur werden ausgewertet, und __New wird (ohne Parameter) aufgerufen, bevor irgendwelche Initialisierer in der äußeren Struktur ausgeführt werden.

Hinweis: Aufgrund der speziellen Anforderungen bezüglich Speicherreservierung und Initialisierung werden verschachtelte Strukturen direkt konstruiert, nicht durch Aufruf der statischen Call-Methode der Klasse.

Wenn die äußere Struktur gelöscht wird, wird zunächst __Delete für die äußere Struktur aufgerufen, danach für jede verschachtelte Struktur (sofern definiert) in umgekehrter Reihenfolge ihrer Definition. Der Speicher der äußeren Struktur wird erst gelöscht, nachdem alle Destruktoren aufgerufen wurden.

Die Eigenschaft, die einer verschachtelten Struktur entspricht, gibt standardmäßig eine Referenz zurück, die auf die verschachtelte Struktur verweist, und ist nicht zuweisbar. Dies kann durch die Definition eines Getters und/oder Setters für die __Value-Eigenschaft überschrieben werden. Wenn ein Setter, aber kein Getter definiert ist, wird standardmäßig die Struktur selbst zurückgegeben.

Abstrakte Typen

Mit einer Struktur können verschiedene abstrakte Typen implementiert werden, wie z.B. smarte Pointer, Arrays, Enums, spezialisierte Zeichenkettentypen oder Typen, die auf bestimmte Werte beschränkt sind. Das folgende Beispiel implementiert einen booleschen Typ ähnlich wie in C++: 

struct bool {
    value : UInt8  ; Dieser Eigenschaftsname hat keine besondere Bedeutung.
    __value {
        get => this.value
        set => this.value := !!value
    }
}

struct Beispiel {
    bInformed : bool
    __new() {
        for Wert in [false, "wahr", 3] {
            this.bInformed := Wert
            MsgBox Wert " konvertiert zu " this.bInformed
        }
    }
}

Beispiel()

Die __Value-Eigenschaft wird auch von DllCall verwendet. Wenn z.B. die Bool-Klasse als DllCall-Parametertyp verwendet wird, wird jeder eingehende Parameterwert wegen !!value automatisch in 0 oder 1 umgewandelt.

Es gibt eine Vielzahl von Konventionen für Zeichenketten in Strukturen und DllCall. Derzeit unterstützen typisierte Eigenschaften intern keine Zeichenketten oder Arrays, können jedoch mithilfe dieser Mechanismen implementiert werden. Die Beispiele CString und BSTR veranschaulichen dies.

Pointer auf Strukturen [v2.1-alpha.22+]

Jede Strukturklasse hat eine statische Eigenschaft namens Ptr, die eine Pointerklasse zurückgibt. Eine Pointerklasse wird in der Regel nicht instanziiert, sondern zusammen mit DllCall und typisierten Eigenschaften verwendet, um einen Parameter oder ein Feld anzugeben, der bzw. das auf eine Struktur verweist. Zum Beispiel repräsentiert RECT.Ptr den C-Typ RECT* oder LPRECT, sofern entsprechend eine Definition der RECT-Strukturklasse vorhanden ist.

Gekapselter Pointer

Anstatt Pointerwerte als eigenständigen Typ zu kapseln, werden sie als Instanzen der Zielstrukturklasse behandelt, mit denselben Eigenschaften und derselben Typidentität. Zur besseren Unterscheidung bezeichnen wir eine vom Skript konstruierte Instanz als "gekapselte Struktur" und eine Instanz, die einen Pointerwert kapselt, als "gekapselter Pointer".

Eine Adresse (Pointerwert) kann durch Aufruf der At-Methode gekapselt werden.

Ref := StructKlasse.At(Adresse)

Da Ref als Instanz von StructKlasse behandelt wird, ist Ref is StructKlasse && Ref.Ptr = Adresse wahr, und Ref.Size gibt die Größe der Struktur (definiert durch die Klasse) zurück. Das bedeutet: Wenn Ref an einen von DllCall genutzten Ptr-Parameter, NumGet oder NumPut übergeben wird, handelt es sich bei dem Parameterwert bzw. der Zieladresse um die Adresse der Struktur, nicht um die Adresse, auf der der Pointer gespeichert ist.

Die Lebensdauer der eigentlichen Struktur ist unabhängig von der Lebensdauer eines gekapselten Pointers – die "Kapsel" enthält lediglich den Pointer, nicht die Struktur. Die meisten Strukturen stammen aus externen Quellen; die Art der Speicherreservierung kann variieren und ist ggf. unbekannt. Das Skript muss sicherstellen, dass nach dem Löschen der Struktur keine typisierten Eigenschaften mehr abgefragt werden.

Warnung: Der Debugger kann Eigenschaften automatisch abfragen. Deshalb sollten gekapselte Pointer am besten immer freigegeben werden, bevor die Zielstruktur gelöscht wird.

Da die Struktur vermutlich bereits konstruiert wurde (in der Regel durch externen Code), werden __Init und __New nicht von At aufgerufen.

Es können beliebig viele gekapselte Pointer für eine bestimmte Adresse existieren, sogar mit unterschiedlichen Klassen. Verschiedene Instanzen werden nicht als gleich angesehen; die "Kapseln" werden verglichen, nicht die Pointerwerte.

DllCall

Verwendet man StructClass.Ptr als DllCall-Parametertyp, wird es ähnlich wie ein Typ mit dem Sternchen/P-Suffix behandelt. Das heißt, der Parameter akzeptiert eine VarRef, einen Wert des Basistyps oder einen Wert, der in den Basistyp umgewandelt werden kann. Wird eine VarRef übergeben, wird der Wert nach dem Aufruf zurückgelesen und der VarRef zugewiesen, wobei der Wert dabei ggf. konvertiert wird. Konkret heißt das:

  • Wenn ungesetzt, wird ein Null-Pointer (0) übergeben.
  • Wenn ein StructKlasse.Ptr übergeben wird, wird der darin enthaltene Pointerwert übergeben (untypische Verwendung).
  • Wenn eine VarRef übergeben wird, wird ihr Wert (sofern vorhanden) als Eingabe verwendet.
  • Wenn die Eingabe eine Instanz von StructKlasse ist, wird deren Adresse übergeben.
  • In allen anderen Fällen wird eine neue Instanz von StructKlasse konstruiert.
    • Wenn ein Eingabewert angegeben wurde (keine ungesetzte VarRef), wird __Value für die Umwandlung zugewiesen. Es wird ein TypeError ausgelöst, wenn __Value nicht implementiert ist.
    • Wenn eine VarRef übergeben wurde, wird der VarRef einer der folgenden Werte zugewiesen:
      • Der Rückgabewert des __Value-Getters, sofern definiert.
      • Die neue Strukturinstanz. StructKlasse.Ptr, &Arg liefert dasselbe Endergebnis wie StructClass.Ptr, Arg := StructKlasse(), außer dass Arg erst nach dem Aufruf etwas zugewiesen bekommt.

Wenn der Rückgabewert als Rückgabetyp verwendet wird, ist er ein gekapselter Pointer, oder ungesetzt, falls Null.

Pointer in Strukturen

Eine Pointerklasse kann als Typ eines Strukturfelds oder einer typisierten Eigenschaft verwendet werden.

Sowohl bei der Zuweisung als auch bei der Rückgabe repräsentiert ungesetzt einen Null-Pointer (0).

Bei ungleich Null ist der High-Level-Wert der Eigenschaft eine Instanz der Zielklasse (entweder ein gekapselter Pointer oder eine gekapselte Struktur).

Wenn der Eigenschaft eine gekapselte Struktur eines geeigneten Typs zugewiesen wird, wird eine Referenz darauf beibehalten, um sicherzustellen, dass diese Struktur erst gelöscht wird, wenn das Skript seine Referenz auf die äußere Struktur oder den gekapselten Pointer freigibt. Zum Beispiel ist die Verwendung von outer.lpEx := Beispiel() in der Regel unbedenklich, während meineVar := Beispiel().Ptr die neue Struktur unmittelbar nach der Zuweisung freigeben würde. Wenn der zugrunde liegende Pointerwert verändert wurde, bewirkt die Auswertung von outer.lpEx, dass die zuvor gehaltene Referenz freigegeben wird.

Wenn eine Pointerklasse direkt konstruiert wird, verhält sich ihre __Value-Eigenschaft wie oben beschrieben.

Strukturierte Arrays [v2.1-alpha.23+]

Strukturierte Arrays haben eine feste Größe und alle ihre Elemente müssen vom gleichen Typ sein. Sowohl die Array-Länge als auch der Elementtyp werden von der Klasse definiert, die eine Unterklasse von Struct.Array ist. Die Unterklasse entsteht nicht durch eine Klassendefinition im Skript, sondern durch die Nutzung der statischen __Item-Eigenschaft einer Struct-Unterklasse. Zum Beispiel:

struct X {
    y : Int32[10]
}
z := X()
MsgBox z.Size ; 40
MsgBox z.y.Size ; 40
MsgBox z.y.Length ; 10
MsgBox z.y is Int32[10] ; wahr
MsgBox z.y is Int32[100] ; falsch

struct XX {
    items : X[2]
}
zz := XX()
MsgBox zz.Size ; 80

Siehe auch

  • ObjGetDataPtr: Gibt die Adresse der strukturierten Daten des Objekts zurück.
  • ObjGetDataSize: Gibt die Größe der Struktur des Objekts in Bytes zurück.
  • ObjSetDataPtr: Setzt die Adresse der strukturierten Daten des Objekts.

Beispiele

Meldet den Klassennamen des Fensters/Steuerelements, auf dem sich der Mauszeiger befindet.

struct Point {
    x : Int32, y : Int32
}

; Mit der Klasse selbst als Wert übergeben (C-Typ: POINT).
WindowFromPoint := DllCall.Bind("WindowFromPoint", Point, unset, "uptr")

; Mit "ptr" per Referenz ohne Typüberprüfung übergeben (C-Typ: POINT*).
GetCursorPos := DllCall.Bind("GetCursorPos", "ptr", unset)
pt1 := Point()
GetCursorPos(pt1)
MsgBox WinGetClass(WindowFromPoint(pt1))

; Mit .Ptr per Referenz übergeben oder Ausgabe via VarRef empfangen.
GetCursorPos := DllCall.Bind("GetCursorPos", Point.Ptr, unset)
GetCursorPos(&pt2)
MsgBox WinGetClass(WindowFromPoint(pt2))

Ruft Informationen über den Bildschirm ab, auf dem sich der Mauszeiger befindet, wobei verschachtelte Strukturen verwendet werden.

struct RECT {
    Left : Int32
    Top : Int32
    Right : Int32
    Bottom : Int32
}

struct MONITORINFO {
    cbSize : Int32 := 40
    rcMonitor : RECT
    rcWork : RECT
    dwFlags : Int32
}

DllCall("GetCursorPos", "uint64*", &point:=0)
hMonitor := DllCall("MonitorFromPoint", "int64", point, "uint", 0, "ptr")
DllCall("user32\GetMonitorInfo", "ptr", hMonitor, "ptr", MI := MONITORINFO())
MsgBox(
(
    "Bildschirminfos vom Punkt:
    Links: " MI.rcMonitor.Left "
    Oben: " MI.rcMonitor.Top "
    Rechts: " MI.rcMonitor.Right "
    Unten: " MI.rcMonitor.Bottom "
    ABLinks: " MI.rcWork.Left "
    ABOben: " MI.rcWork.Top "
    ABRechts: " MI.rcWork.Right "
    ABUnten: " MI.rcWork.Bottom "
    Primär: " MI.dwFlags
))

Definiert eine Struktur, die eine Zeichenkette fester Größe in einer bestimmten Kodierung enthält.

; Eine wiederverwendbare "Metaklasse" oder "generische Klasse" für C-artige
; Zeichenketten definieren. Der Aufruf von CString selbst gibt eine neue Klasse
; zur Verwendung in einem Typausdruck zurück.
CString(n, cp:="UTF-16") {
    c := Class(Struct)
    unitSize := StrPut("", cp)  ; Größe in Bytes eines einzelnen "Zeichens".
    DefineProp(c.Prototype, '_chars', {type: unitSize=2 ? UInt16[n] : Int8[n]})
    DefineProp(c.Prototype, '__value', {
        get: (this)        => StrGet(this,, cp),
        set: (this, value) => StrPut(value, this,, cp)
    })
    return c
}

; Struktur definieren, die eine Zeichenkette mit höchstens
; 32 UTF-8-Codeeinheiten enthält.
struct XStruct {
  str : CString(32, "UTF-8")
}

x := XStruct()
x.str := "Hallo!"
MsgBox x.str

Definiert eine Struktur, die Zeichenkettenumwandlungen in/von BSTR durchführt.

MsgBox DllCall("oleaut32\SysStringLen", BSTR, "abc" Chr(0) "123")
MsgBox DllCall("oleaut32\SysAllocString", "wstr", "xyz", BSTR)

struct BSTR {  ; Dieser Typ kann auch in einer Struktur verwendet werden.
    ptr : IntPtr
    size => DllCall("oleaut32\SysStringByteLen", "ptr", this, "uint")
    __value {
        get => StrGet(this)
        set {
            if this.ptr  ; Bei Verwendung in einer Struktur.
                this.__delete()
            this.ptr := DllCall("oleaut32\SysAllocStringLen", "wstr", value, "uint", StrLen(value), "ptr")
        }
    }
    __delete() => DllCall("oleaut32\SysFreeString", "ptr", this)
}

Ruft eine Funktion auf, die eine Struktur als Wert zurückgibt.

struct lldiv_t {
    quot : Int64, rem : Int64
}
res := DllCall("ucrtbase\lldiv", "int64", 31558149, "int64", 3600, lldiv_t)
MsgBox Format("Erdumlaufbahn: {} Stunden und {} Sekunden.", res.quot, res.rem)

Definiert eine Rückgabetyp-Struktur für Fehlerprüfung und automatisches Aufräumen.

struct LoadedHModule {
    h : IntPtr
    __value => this.h ? this : throw(OSError(A_LastError, -1))
    __delete() => DllCall("FreeLibrary", "ptr", this.h)
}

check
gdip := DllCall("LoadLibrary", "str", "gdiplus", LoadedHModule)
check
gdip := unset
check

DllCall("LoadLibrary", "str", "das muss scheitern", LoadedHModule) ; OSError(126)

; Im Gegensatz zu LoadLibrary wird bei GetModuleHandle ein Rückgabewert von Null
; erwartet, und ein Handle ungleich Null sollte nicht automatisch freigegeben werden.
check() => MsgBox(DllCall("GetModuleHandle", "str", "gdiplus", "ptr") ? "Geladen" : "Nicht geladen")
