Module [v2.1-alpha.11+]

Ein Modul ist im Grunde ein Skript innerhalb des Skripts. Jedes Modul hat einen eigenen:

  • Globalen Namensraum für Variablen, Funktionen und Klassen.
  • Körper, der manchmal auch als automatischer Ausführungsbereich bezeichnet wird.

Durch die Aufteilung eines Skripts in Module lassen sich seine Bestandteile leichter wiederverwenden und pflegen.

Standardmäßig werden alle Codezeilen und globalen Variablen (einschließlich Funktionen und Klassen) einem implizit definierten Modul namens "__Main" hinzugefügt. Das Skript kann mit #Module ein neues Modul starten oder mit #Import ein Modul aus einer Datei laden.

Mit einer #Import-Direktive kann ein Modul oder einige seiner Funktionen, Klassen und Variablen innerhalb des aktuellen Moduls zugänglich gemacht werden.

Alle Module importieren implizit aus dem internen Modul "AHK", das alle internen Klassen, Variablen und Funktionen enthält. Eine Deklaration oder Zuweisung innerhalb eines Moduls kann den Namen einer internen Klasse oder Funktion wiederverwenden. In diesem Fall ist die entsprechende Klasse oder Funktion nur über das AHK-Modul zugänglich (z.B. #Import AHK, AHK.MsgBox()). Interne Variablen (A_) lassen sich ohne Deklaration oder Import zuweisen, und ihre Namen sind nicht wiederverwendbar. A_Args ist eine Ausnahme (es ist eine normale in __Main definierte Variable).

Ein Modulname gelangt erst durch den Import in den globalen Namensraum eines Moduls; etwaige Konflikte lassen sich durch ein Alias für das importierte Modul im Zielmodul lösen.

#Include kann jeweils nur eine Datei pro Modul inkludieren.

Mit #Warn können Warnungen innerhalb des aktuellen Moduls aktiviert oder deaktiviert werden, ohne dass andere Module davon betroffen sind. Weitere Informationen finden Sie in den #Warn-Bemerkungen.

#HotIf beeinflusst nur das aktuelle Modul. #HotIf und HotIf-Ausdrücke gelten nur innerhalb ihres Moduls, da sie Referenzen enthalten können, die auf Variablen im Modul verweisen. Zum Beispiel ist der Effekt von #HotIf meinSchalter davon abhängig, welchen Wert meinSchalter im aktuellen Modul hat.

Ausführung

Sobald das Programm gestartet wird, wird der Körper jedes Moduls vom Auto-Execute-Thread ausgeführt. Die Ausführung startet mit dem zuletzt definierten oder geladenen Modul. Enthält das Modul keine Importe, wird als Nächstes das vorletzte Modul ausgeführt. Dies wiederholt sich, bis alle Module ausgeführt wurden.

[v2.1-alpha.21+]: Wird eine Variable oder Konstante eines Moduls referenziert, bevor dessen Ausführung begonnen hat, wird das Modul sofort ausgeführt. Die #Import-Direktive selbst hat keinen Einfluss auf die Reihenfolge. Zum Beispiel:

#Module A
MsgBox "A wird ausgeführt"  ; wird als Zweites angezeigt.
global ANTWORT := 42

#Module B
#Import A {ANTWORT}
MsgBox "B wird ausgeführt"  ; wird als Erstes angezeigt.
MsgBox ANTWORT         ; wird als Drittes angezeigt.

[v2.1-alpha.20] und älter: Jedes Modul führt seine importierten Module vor seinem eigenen Körper aus, mit Ausnahme von bereits gestarteten Modulen. Das funktioniert jedoch weniger gut, wenn Module zirkuläre Abhängigkeiten aufweisen.

Suchpfad [v2.1-alpha.20+]

Der Modulsuchpfad ist eine Liste von Verzeichnissen, die von der #Import-Direktive genutzt wird, um Moduldateien zu finden. Das Verzeichnis der Datei, die die #Import-Direktive enthält, wird immer zuerst durchsucht. Die Umgebungsvariable AhkImportPath kann eine semikolongetrennte Liste von Verzeichnissen enthalten, die ebenfalls durchsucht werden sollen. Wenn diese Variable nicht verwendet wird, gilt die folgende Standardliste:

%A_ScriptDir%;%A_MyDocuments%\AutoHotkey;%A_AhkPath%\..

Interne Variablen können in der Liste angegeben werden, müssen aber in Prozentzeichen gesetzt werden. Prozentzeichen, die nicht zu einer gültigen Variablenreferenz gehören, werden als direkt geschriebener Text interpretiert. Referenzen, die auf Umgebungsvariablen verweisen, werden von AutoHotkey nicht aufgelöst, da dies in der Regel bereits vor dem Prozessstart erfolgt. Die Einträge in der Liste können absolute Pfade oder relativ zum Verzeichnis des Skripts (A_ScriptDir) sein. Die Liste wird nur einmal aufgelöst, daher verweist A_LineFile immer auf das Hauptskript.

Die Verzeichnisse werden in der Reihenfolge ihrer Auflistung durchsucht. Innerhalb jedes Verzeichnisses werden die Dateien in folgender Reihenfolge abgearbeitet:

  • ModulName
  • ModulName\__Init.ahk
  • ModulName.ahk

Zum Beispiel könnte #Import M die Datei mit dem exakten Namen M, M\__Init.ahk oder M.ahk laden. #Import "M" verhält sich genauso, nur dass der Name M nicht zum aktuellen Modul hinzugefügt wird.

Beispiele

Jedes Modul hat seine eigenen globalen Variablen (MeineVar und VarZeigen).

#Import Anderes  ; Benötigt v2.1-alpha.20+.
MeineVar := 1
VarZeigen()  ; Unsere MeineVar ist 1.
Anderes.VarZeigen()  ; Andere MeineVar ist immer noch 2.
MsgBox "Im Haupt, Anderes.MeineVar = " (Anderes.MeineVar ?? "unzugänglich")  ; MeineVar ist zugänglich in v2.1-alpha.19+.
VarZeigen() => MsgBox("Haupt MeineVar = " MeineVar)

#Module Anderes
MeineVar := 2
VarZeigen() => MsgBox("Anderes MeineVar = " MeineVar)

Verwenden Sie ein Alias, um einen Konflikt zu lösen. Jedes Modul hat sein eigenes Berechnen, das Vorrang vor jedem Platzhalterimport hat.

#Import "X" {Berechnen as XBerechnen}
#Import "Y" {*}

MeineVar := 1
MsgBox Berechnen()
MsgBox XBerechnen()
MsgBox Prüfen(3)
MsgBox "X = " (X ?? "nicht importiert")
MsgBox "Y = " (Y ?? "nicht importiert")

Berechnen() => 1

#Module X
Berechnen() => 2

#Module Y
Berechnen() => 3
Prüfen(n) => n = Berechnen()

Zugriff auf "überschriebene" interne Funktionen.

#Import AHK

MsgBox "Hallo, Welt!",, "T2"

; Infosymbol standardmäßig hinzufügen.
MsgBox(Text?, Titel?, Optionen:="") {
    return AHK.MsgBox(Text?, Titel?, "Iconi " Optionen)
}

#Module Anderes
MsgBox "Anderes hat noch die originale MsgBox.",, "T2"
